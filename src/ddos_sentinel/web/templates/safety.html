Small scope. Visible limits.

The network boundary

All traffic targets a temporary service owned by this application on 127.0.0.1. Public IPs, public domains, private network targets, arbitrary URLs, DNS resolution, environment proxies, and redirects are unavailable. Only built-in HTTP endpoints are used.

Consent and ceilings

Every simulation, including dry runs, requires fresh explicit authorization. Fixed ceilings are 60 seconds, 200 requests/second, 100 synthetic clients and 65,536 bytes per body. Your configuration may lower these limits. Cancellation stops and awaits client tasks.

Local, reversible controls

Mitigation applies inside the owned test service. Actions need reasons, expire in at most 300 seconds, and support manual reset. The application never changes the OS firewall, executes configured commands, or loads traffic scripts.

Privacy and uncertainty

Only request metadata is retained. No bodies, cookies, authorization headers or capability tokens are stored. Synthetic client labels do not spoof addresses. An anomaly is evidence of an unusual workload; it is not proof of an attack. Baseline quality matters.

Trust assumptions

Run on a trusted single-user machine. The dashboard binds to loopback and validates Host, Origin, CSRF and control inputs. It is not a multi-user authentication service. Keep analyst notes and reasons free of secrets.

What this lab covers

This is a defensive teaching and incident-measurement lab. It does not replace upstream DDoS protection, an ISP, CDN, WAF, production load testing, network IDS/IPS, SIEM or EDR. It must never be used against systems without authorization.
